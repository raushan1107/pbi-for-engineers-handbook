Module 7

Report Design & Visualization

A model full of correct measures does no good if the report is confusing, slow, or misleading. Effective report design is about matching the right visual to the right question, arranging information so the most important insight appears first, and building interactivity that feels intuitive — not cluttered. This module covers the principles and then applies them to build a three-page RR EngineerWorks dashboard.

⏱ ~3 hours 📋 6 topics + 1 lab 🎯 Workflow stage: Visualize 📊 Builds 3-page dashboard

Choosing the Right Visual

Match the Visual to the Question
Question typeBest visualAvoid
How much? (single KPI) Card, KPI Bar chart for a single number
How does it change over time? Line chart, Area chart Pie chart — hides the time dimension
How do categories compare? Bar chart (vertical for <8 items), Column chart Pie/donut for more than 5 segments
Part-to-whole (few segments) Donut chart, Stacked bar Pie with 10+ slices
Two measures by category Clustered bar, Combo chart (bar + line) Side-by-side lines with different scales
Distribution / spread Scatter chart, Histogram (via custom visual) Bar chart with too many bins
Ranking with detail Table, Matrix A visual alone when exact numbers matter
Geographic data Map visual, Filled Map Bar chart when spatial pattern is the insight
The Engineer's Default: Tables Are Not a Last Resort

Engineers often prefer tables — exact numbers over approximate chart readings. This is correct for technical audiences. For executive or operations audiences, charts communicate trends and comparisons faster. A well-designed dashboard uses both: a summary visual at the top for quick scanning, a detailed table at the bottom for drill-down.

Layout & Design Principles

The Z-Pattern and F-Pattern

Readers scan screens in a Z-pattern (top-left → top-right → bottom-left → bottom-right) or an F-pattern (horizontal scan at top, then vertical scan down the left side). Place the most important KPIs in the top-left zone and supporting detail lower and to the right.

Layout Rules for Power BI Reports
  • Top strip (10–15% of height): Page title, period selector slicer, high-level KPI cards
  • Left column or top-left quadrant: Primary chart (the main analytical view)
  • Right column or top-right: Secondary charts or breakdown
  • Bottom section: Detail table for drill-down
  • Slicers: Either top-right or a dedicated left panel — never scattered across the canvas
Formatting Essentials
SettingWhereRecommendation
Canvas backgroundView → Canvas backgroundLight grey (#F5F5F5) reduces glare vs. pure white
Visual bordersFormat pane → General → Effects → ShadowSubtle shadow instead of heavy borders
Data labelsFormat pane → Data labelsEnable for bar/column charts; disable for line charts with many points
Axis titlesFormat pane → X-axis / Y-axis → TitleRemove when the visual title makes the axis obvious
LegendFormat pane → LegendMove to Top when space allows; disable when only one series
GridlinesFormat pane → GridlinesReduce opacity to 30–40%; delete vertical gridlines on bar charts
Colour paletteFormat pane → ColorsPick 2–3 brand colours; use accent colour for the highlighted measure only
4

Drill-Down, Tooltips & Bookmarks

Drill-Down with Hierarchies

When a hierarchy is on a visual's axis, the drill-down arrows appear in the visual header (the double-down arrow). Clicking drills into the next level for the selected data point. Clicking the down-arrow at the header expands all data points to the next level simultaneously.

For example: a line chart with the Date Hierarchy (Year → Quarter → MonthName → Date) on the X axis can drill from annual summary down to daily detail without changing the report layout.

Tooltips

By default, hovering over a data point shows the axis and value fields. You can add more fields to the Tooltips field well of a visual to show additional context on hover — without cluttering the visible chart.

Tooltip pages: Create a dedicated report page, set its size to "Tooltip" in Page information (e.g. 320×240), mark it as a Tooltip page, and assign it to any visual via Format pane → Tooltips → Page. This creates rich mini-reports that appear on hover.

Bookmarks

Bookmarks capture the current state of a report page — which visuals are visible, which slicers are active, the current drill level — as a named snapshot. You can assign a bookmark to a button to create navigation or "reset filters" functionality without building a separate page.

Common pattern: a "Reset All Filters" button that triggers a bookmark of the page with all slicers cleared, allowing users to get back to the default view with one click.

Conditional Formatting

Where to Apply It

In a Table or Matrix visual, select a value column → in the Format pane, expand the column's settings → click Conditional formatting. You can apply formatting to:

  • Background colour: Colour the cell based on the value
  • Font colour: Change text colour based on value
  • Data bars: Horizontal bar within the cell proportional to the value
  • Icons: Traffic lights, arrows, or custom icon sets
Rules vs Gradient vs Field Value
MethodWhen to useExample
Gradient Continuous range where low-to-high maps to colour scale Heat map of sales by region: white → dark green
Rules Discrete thresholds with specific colours Red if < 0, yellow if 0–10%, green if > 10%
Field value A measure or column controls the colour via a hex code string A DAX measure that returns "#FF4444" for negative, "#22AA44" for positive

Sales & Finance Report Design

Standard Sales Report Structure

A well-designed sales report answers four questions in sequence:

  1. Are we on track? — KPI cards for Total Sales vs Target, period YTD
  2. Where are we winning or losing? — Bar chart comparing regions or products
  3. What is the trend? — Line chart of monthly sales and a YTD line
  4. What exactly happened? — Detail table with row-level values for investigation
Report for Engineers vs Report for Managers
Engineering audienceManagement audience
PrefersTables, exact numbers, scatter plots, technical labelsCards, bar charts, trend lines, plain English labels
Context neededData source, sample size, methodology notesPeriod covered, comparison baseline, target line
InteractionDrill to row level; export to ExcelSlicers for period and region; guided drill-down
Page count1–2 dense pages acceptable3–4 focused pages preferred

The RR EngineerWorks report is designed for both — a Management Summary page at a high level, and detailed Sales Performance and Production Overview pages for the operations team.

Hands-On: Build the RR Dashboard

You will build a three-page report in RR_EngineerWorks_v6.pbix: Sales Performance, Production Overview, and Management Summary. Each lab builds one page. Follow the steps in order — some visuals on later pages re-use formats from earlier pages.

Lab 7A — Page 1: Sales Performance
1
Rename the default page and set canvas size

Open RR_EngineerWorks_v6.pbix. At the bottom, double-click Page 1 → rename it to Sales Performance.

In the View tab, confirm Canvas size is set to 16:9 (the default, 1280×720).

2
Add the page title text box

Insert → Text box. Type Sales Performance. Format: font size 20, bold. Position at top-left. Add a sub-label text box: RR EngineerWorks — 2024 Full Year, font size 11.

3
Add three KPI Card visuals (top strip)

Add three Card visuals across the top of the canvas:

  • Card 1: Field = [Total Sales]. Title: "Total Sales 2024"
  • Card 2: Field = [Total Orders]. Title: "Total Orders"
  • Card 3: Field = [Sales vs Target %]. Title: "vs Target"

For each card: Format pane → Callout value → font size 28. General → Title → On, text as above, font size 11.

4
Add a Line chart: Monthly Sales trend

Add a Line chart. Configure field wells:

  • X axis: Dim_Date[MonthName] (use the MonthName field, not the hierarchy — it sorts by Month automatically because of the Sort by Column setting from Module 4)
  • Y axis: [Total Sales]
  • Secondary Y axis: [Total Sales YTD]

Format: enable Data labels for the primary series (monthly sales). Add a title: "Monthly Sales and YTD". Enable the legend to distinguish the two series.

5
Add a Clustered Bar chart: Sales vs Target by Region

Add a Clustered bar chart. Configure:

  • Y axis (category): Dim_Regions[RegionName]
  • X axis (values): [Total Sales] and [Total Target]

Sort the bars by Total Sales descending: click the … menu on the visual → Sort axis → Total Sales → Sort descending. Title: "Sales vs Target by Region".

6
Add a detail Table

Add a Table visual at the bottom. Add these columns in order:

  • Dim_Regions[RegionName]
  • [Total Sales]
  • [Total Target]
  • [Sales vs Target]
  • [Sales vs Target %]
  • [Region Sales Rank]

Sort by Region Sales Rank ascending (rank 1 = top region at the top of the table).

7
Apply conditional formatting to Sales vs Target

In the Table visual, click on the [Sales vs Target] column header → Format pane → scroll to that column's settings → expand Conditional formatting → enable Background colour.

Set up Rules-based formatting:

  • If value is < 0 → background colour Red (#FF6B6B)
  • If value is ≥ 0 → background colour Green (#6BCC88)

Also enable Data bars on the [Total Sales] column with a dark blue fill colour.

8
Add slicers

Add two Slicer visuals:

  • Slicer 1: Field = Dim_Products[Category]. Style: Dropdown (Format pane → Slicer settings → Style → Dropdown). Title: "Filter by Category"
  • Slicer 2: Field = Dim_Date[QuarterName]. Style: Tile. Title: "Quarter"

Position both slicers to the right of the line chart or in a row below the KPI cards.

✓ Lab 7A Complete
  • 3 KPI cards show Total Sales, Total Orders (585), and Sales vs Target % values
  • Line chart shows 12 monthly bars/points with an increasing YTD secondary line
  • Clustered bar shows 10 regions, each with a Sales bar and a Target bar, sorted by Sales descending
  • Detail table shows 10 rows, green/red conditional formatting on Sales vs Target column
  • Category slicer filters all visuals simultaneously when a Category is selected
Lab 7B — Page 2: Production Overview
1
Add a new page and rename it

Click the + at the bottom to add a new page. Rename it Production Overview.

2
Add KPI cards (top strip)

Add three Card visuals:

  • Card 1: [Total Actual Units] — Title: "Actual Units Produced"
  • Card 2: [Total Planned Units] — Title: "Planned Units"
  • Card 3: [Production Efficiency %] — Title: "Production Efficiency"
3
Add a Clustered Column chart: Planned vs Actual by Category

Add a Clustered column chart. Configure:

  • X axis: Dim_Products[Category]
  • Y axis: [Total Planned Units] and [Total Actual Units]

Title: "Planned vs Actual Production by Category". Enable data labels.

Note: Fact_Production links to Dim_Products via ProductCode. Dim_Products has a Category column (split from Category_SubCategory in Module 3). Only physical products appear in Fact_Production — the generator excludes service products from production runs. Expect ~4–5 categories in this visual, not all product categories.

4
Add a Line chart: Production Efficiency by Month

Add a Line chart. Configure:

  • X axis: Dim_Date[MonthName]
  • Y axis: [Production Efficiency %]

Format: Y axis minimum = 0.5 (50%), maximum = 1.2 (120%), to focus the view on the meaningful range. Add a constant line at Y = 1.0 (100% efficiency) via Analytics pane → Constant line → Value: 1. Title: "Production Efficiency by Month".

5
Add a detail Table: Production by Product

Add a Table visual with:

  • Dim_Products[ProductName]
  • Dim_Products[Category]
  • [Total Planned Units]
  • [Total Actual Units]
  • [Production Efficiency %]

Apply conditional formatting on [Production Efficiency %]: gradient from red (0%) through yellow (80%) to green (100%+). Sort by Efficiency descending.

6
Add a Slicer for Plant

Fact_Production has a Plant column (text field with values like "Manchester Plant", "Birmingham Plant", "Edinburgh Plant"). Add a Slicer with Fact_Production[Plant] and title "Filter by Plant".

This slicer filters Fact_Production directly. Since Plant is not in a dimension table, it is not hidden — this is a fact table column used as a slicer, which is acceptable when the column has low cardinality (3 distinct values).

Lab 7C — Page 3: Management Summary
1
Add a third page: Management Summary

Click + → rename to Management Summary. This page is a one-glance overview. Keep it sparse — fewer visuals, larger text.

2
Add four large KPI Cards

Create four Card visuals in a 2×2 grid in the top-left:

  • [Total Sales] — "2024 Revenue"
  • [Total Target] — "2024 Target"
  • [Production Efficiency %] — "Production Efficiency"
  • [Sales vs Target %] — "Sales vs Target"

Callout value font size: 36 for all four cards.

3
Add a Matrix: Sales by Category and Region

Add a Matrix visual. Configure:

  • Rows: Dim_Products[Category]
  • Columns: Dim_Regions[RegionName]
  • Values: [Total Sales]

Enable Row subtotals and Column subtotals in Format pane → Row subtotals / Column subtotals → On. Apply conditional formatting (gradient) on the values to create a heat map effect.

4
Add a Bar chart: Region Sales Rank

Add a Bar chart. Configure:

  • Y axis: Dim_Regions[RegionName]
  • X axis: [Total Sales]

Sort bars by Total Sales descending. Add data labels showing the sales value. Title: "Revenue by Region". This gives management a quick regional league table.

5
Add a Quarter slicer and a "Reset" button

Add a Slicer with Dim_Date[QuarterName] (tile style). Then: capture a bookmark of this page with no slicers selected (View → Bookmarks → Add; name it "Reset Filters").

Insert → Button → Reset (or any button). In the Format pane → Action → On → Type: Bookmark → Bookmark: Reset Filters. Label the button "Reset Filters". Now clicking this button returns all slicers on the page to their default (all selected) state.
