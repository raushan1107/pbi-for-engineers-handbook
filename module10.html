Module 10

Capstone: End-to-End Solution

This is where everything comes together. You choose a real analytical challenge, build a complete Power BI solution from raw data to published report, and present your findings using the storytelling techniques from Module 8. No scaffolding — just your skills, the dataset, and a blank canvas.

⏱ ~4–6 hours 📋 4 stages + presentation 🎯 All modules applied 🏆 Final project
1

Choose Your Scenario

How the Capstone Works

You will build a completely new Power BI report against the RR EngineerWorks semantic model from scratch — not extending the report from previous modules, but starting a new .pbix file connected to the same dataset. This simulates the real-world situation where a new stakeholder asks for a fresh analytical view of data you already know.

Choose one of the three scenarios below. Each targets a different audience and requires a different analytical focus, but all use the same underlying tables. Pick the one that most closely matches your professional context or the one that challenges you most.

Scenario A — Regional Sales Manager Dashboard

Audience: 10 regional sales managers, each responsible for one region.

Business question: Which regions are on track against their 2024 sales targets, and what product mix is driving or dragging performance?

Required views:

  • Page 1: Region overview — KPI cards for Total Sales, Target, Variance to Target, and Attainment %; top 5 customers by revenue; month-on-month trend.
  • Page 2: Product breakdown — category and subcategory sales with conditional formatting to highlight underperformers; drill-through to product detail.
  • Page 3: Sales rep analysis — orders and revenue by SalesRepName; average order value; order status distribution.

Security requirement: Dynamic RLS — each manager sees only their own region's data using USERPRINCIPALNAME() and a UserRegionMap table.

Scenario B — Production Operations Dashboard

Audience: Plant managers and the operations director.

Business question: Are the three production plants operating efficiently, and how does actual output compare to planned targets across products and months?

Required views:

  • Page 1: Plant performance — production volume, efficiency %, and defect rate (ScrapQuantity ÷ QuantityProduced) per plant; gauge or KPI visual for efficiency against a 95% threshold.
  • Page 2: Product production trend — monthly QuantityProduced per product across all plants; production heatmap by plant and month.
  • Page 3: Sales vs production alignment — side-by-side comparison of units sold (Fact_Orders) vs units produced (Fact_Production) per product; flag where sales significantly exceed or underrun production.

New measure required: Defect Rate % = DIVIDE(SUM(Fact_Production[ScrapQuantity]), SUM(Fact_Production[QuantityProduced]), 0) formatted as a percentage.

Security requirement: Static RLS — one role per plant, filtering Fact_Production[PlantID] so each plant manager sees only their own plant's data.

Scenario C — Executive Operations Summary

Audience: C-suite and senior leadership — one page per area, high-level insights, minimal clutter.

Business question: How is the business performing holistically across sales, production, and regional footprint — and what needs immediate attention?

Required views:

  • Page 1: Executive summary — 6 headline KPI cards (Total Sales, Sales vs Target, YoY Growth %, Total Units Produced, Average Order Value, Active Customers); a smart narrative summary; Decomposition Tree for Total Sales.
  • Page 2: Trend dashboard — YTD Sales with PYTD comparison; MoM production trend; regional attainment heatmap.
  • Page 3: What-if scenario — Price increase % slicer; Adjusted Revenue and Adjusted Margin cards; commentary text box explaining the scenario.

Design constraint: All pages must follow the dark theme established in Module 7, use no more than three chart types per page, and include a dynamic report title reflecting active slicer selections.

Security requirement: No RLS needed — executives see all data. Configure workspace App with Viewer access for leadership group only.

Starting File Setup

Create a new .pbix file. Connect it to the RR EngineerWorks semantic model in one of two ways:

  • Option 1 — Live Connection (recommended if published): In the new file, click Home → Get data → Power BI datasets. Select RR_EngineerWorks_v8 from the Service. The model connects live — all tables and measures are available, and you start with a blank report canvas.
  • Option 2 — Copy and strip: File → Save As on RR_EngineerWorks_v8.pbix to create RR_Capstone_[Scenario].pbix. Delete all existing report pages. The model remains intact.

Name the file: RR_Capstone_A.pbix, RR_Capstone_B.pbix, or RR_Capstone_C.pbix depending on your choice.

Stage 1 — Transform

What to Do in This Stage

If you used Option 2 (copy and strip), your Power Query transformations from Modules 2 and 3 are already applied. If you used Option 1 (Live Connection to the Service dataset), no Power Query access is needed — the model is already clean.

For Scenario A and C, no additional transformation is needed.

For Scenario B, create a new calculated column or apply the additional steps below.

Scenario B — Additional Transform: Efficiency %

The existing Fact_Production table has QuantityProduced and PlannedQuantity. In Power Query (if using Option 2), add a custom column: 

= [QuantityProduced] / [PlannedQuantity]

Name the column EfficiencyRatio. Format as a percentage in the data model. Alternatively, compute this as a DAX measure (preferred): 

Efficiency % =
DIVIDE(
    SUM(Fact_Production[QuantityProduced]),
    SUM(Fact_Production[PlannedQuantity]),
    0
)
Scenario A — Additional Table: UserRegionMap

Dynamic RLS requires a UserRegionMap lookup table. Create it using Enter Data (Home → Enter data):

UserEmailRegionName
sarah@yourdomain.comNorth England
james@yourdomain.comMidlands
your-own-email@domain.comSouth England
… one row per manager per region …

Name the table UserRegionMap. Use real email addresses (Microsoft Entra UPNs) for production — for the capstone, you can use your own email to test it. Do not create a relationship between this table and Dim_Regions; it is used only inside the RLS DAX expression.

RLS Role Setup (Scenario A and B)

Scenario A — Dynamic RLS: Create one role named Regional Manager. In the Dim_Regions table filter: 

[RegionName] IN
CALCULATETABLE(
    VALUES(UserRegionMap[RegionName]),
    UserRegionMap[UserEmail] = USERPRINCIPALNAME()
)

Test using Modeling → View as → Regional Manager. You will see data for whatever region is mapped to your own email in the UserRegionMap table.

Scenario B — Static RLS per plant: Create three roles — Plant_P01, Plant_P02, Plant_P03. For each, apply the filter to Fact_Production: 

-- For Plant_P01:
[PlantID] = "P01"

Test each role with View as to confirm the Production pages filter correctly.

Stage 3 — Visualize

Design Constraints for All Scenarios
  • Exactly 3 report pages as specified in your scenario.
  • Consistent colour palette across all pages — pick one from Module 7 or create your own.
  • Every page must have a page title text box with the page name and a subtitle explaining the audience or purpose.
  • At least one page must use conditional formatting (background colour, data bars, or icons) on a table or matrix.
  • At least one page must have a slicer connected to a meaningful dimension (Date, Region, or Category depending on scenario).
  • All measure-based visuals must use measures from _Measures — no implicit aggregations on raw columns in visuals.

Scenario A — Page-by-Page Guidance

Page 1 (Region Overview): Four KPI cards in a row at the top (Total Sales, Target, Variance to Target, Attainment %). Line chart below showing monthly sales trend for the selected region. Bar chart showing Top 5 customers by Total Sales. Slicer for Month (or Quarter).

Page 2 (Product Breakdown): Matrix with Category and SubCategory on rows, Total Sales and Attainment % as values. Apply background colour conditional formatting to Attainment % — red below 80%, yellow 80–100%, green above 100%. Bar chart showing sales by category with a target reference line.

Page 3 (Sales Rep Analysis): Table showing SalesRepName, total orders, Total Sales, Average Order Value — sorted by Total Sales descending. Donut chart showing Order Status distribution (Completed vs Pending vs Cancelled). Card showing Active Customers count.

Scenario B — Page-by-Page Guidance

Page 1 (Plant Performance): Three KPI cards (one per plant) showing Efficiency %. Use conditional formatting — below 90% = red, 90–95% = amber, above 95% = green. A clustered bar showing Total Units Produced vs Total Planned by PlantID. Card for overall Defect Rate %.

Page 2 (Production Trend): Line chart with Month on X axis, Total Units Produced on Y — one line per plant (use legend = PlantID). Matrix with ProductCode on rows, MonthName on columns, QuantityProduced as values — this is the heatmap; apply background colour data bars to the values.

Page 3 (Sales vs Production): Clustered column chart with ProductCode on X axis — two clustered columns: Units Sold and Total Units Produced. Add a calculated measure Production vs Sales Gap as a line on a secondary axis. Table below listing each product's gap value with conditional formatting (positive gap = under-selling; negative = over-selling relative to production).

Scenario C — Page-by-Page Guidance

Page 1 (Executive Summary): Six KPI cards in two rows of three: Total Sales | Sales vs Target | YoY Growth % | Total Units Produced | Average Order Value | Active Customers. Decomposition Tree with [Total Sales] as Analyze and Category, RegionName, SalesChannel, MonthName as Explain by. Smart Narrative visual (auto-generate and clean up the text).

Page 2 (Trend Dashboard): Combo line+column chart: monthly Total Sales (columns) and PYTD Sales (line) side by side. KPI card for YTD Sales with goal = PYTD Sales. Clustered bar chart showing Attainment % by region with 100% reference line and conditional formatting. Year and Quarter slicers.

Page 3 (What-If Scenario): Price Increase % slicer (slider). Two cards: Adjusted Revenue and its delta from Total Sales. A commentary text box explaining the scenario (format it as a "CEO brief" — two sentences of context). Line chart showing Adjusted Revenue by month at the selected uplift rate.

Stage 4 — Publish & Secure

Apply the Module 9 Workflow

This stage applies the skills from Module 9 to your capstone file. Work through each step:

Step 1 — Publish

File → Save as RR_Capstone_[A/B/C].pbix. Click Home → Publish. Select the RR EngineerWorks Analytics workspace created in Module 9 (or create a new workspace named RR Capstone). Select and publish.

Confirm both artefacts appear in the workspace: the report and the semantic model. Open the report in the browser and verify all three pages load correctly.

Step 2 — Assign RLS Members (Scenarios A and B)

In the workspace, open the capstone semantic model's Security settings. Assign users to the roles:

  • Scenario A: Assign yourself or a test account to the Regional Manager role. Test with "Test as role" — confirm you see only the regions mapped to your email in UserRegionMap.
  • Scenario B: Assign test accounts to Plant_P01, Plant_P02, Plant_P03. Test each with "Test as role" — confirm each shows only one plant's production data.
Step 3 — Scheduled Refresh

Configure a daily scheduled refresh for the semantic model. Set a time slot, time zone, and failure notification email. Click Apply. (Actual refresh will succeed only if a gateway connects the source file — configure the Personal Gateway if you want a live refresh.)

Step 4 — Publish App (Scenario C) or Share Report (A and B)

Scenario C: Publish a workspace app named RR Executive Summary. Set the audience to the leadership group or "All people in my organisation." Publish.

Scenarios A and B: Use direct report sharing to share with the test accounts you assigned to RLS roles. Confirm that when those accounts open the report, the data is correctly filtered.

Present Your Insights

Structure Your Presentation Using SCQA

A data presentation without structure is just a gallery of charts. Use the SCQA framework (from Module 8) to turn your capstone report into a story:

LetterWhat to sayExample for Scenario A
Situation Brief context — who is the audience, what is the data, what time period "This dashboard covers 2024 sales performance across 10 regions for RR EngineerWorks."
Complication The problem or tension the data reveals "Three regions — South England, Wales, and Scotland — are more than 15% below target as of Q3."
Question The key question the report answers "What is driving the underperformance, and is it a category issue or a customer issue?"
Answer What the report reveals — click through the visuals to show the answer "Drilling into the product breakdown shows Industrial Equipment sales are 40% below target in all three regions, while Consumer Goods are on track. The top customer in each region has reduced order frequency since Q2."
Live Demo Walkthrough

When demoing the report to an audience — real or simulated — follow this sequence:

  1. Start at the summary page. Let the headline KPIs land before drilling in.
  2. Use slicers intentionally. Start with no filters, then apply one at a time to show how the story changes. Explain why you're filtering.
  3. Narrate the insight, not the visual. Don't say "here is a bar chart showing…" — say "South England is the only region where sales have declined quarter-over-quarter."
  4. Use drill-through or decomposition to answer the "why." Show the audience how they can do this themselves.
  5. End with a recommendation. Data without a next action is incomplete. Close with: "Based on this, I'd recommend we…"
Written Summary (Optional)

As an optional deliverable, write a 200–300 word executive summary of your findings using SCQA. This tests whether the data story is clear enough to be understood without the visual — a good benchmark for quality.

Include: the key metric (what is it?), the key finding (what does it tell us?), the key driver (why is it happening?), and the recommended action (what should we do?).
